# Sources

A source is a declaration of *where desired state lives* and *how often to
look*. source-controller turns that declaration into an artifact (lesson 2).
There are four kinds, and they share most of their fields.

## The four kinds

| Kind | `spec.url` looks like | What is fetched | Typical use |
|---|---|---|---|
| `GitRepository` | `https://…/repo.git`, `ssh://git@…`, `http://…` | A Git tree at a ref | Your manifests, Kustomize overlays, charts kept in Git |
| `OCIRepository` | `oci://ghcr.io/org/manifests` | A tarball pushed with `flux push artifact` | Manifests published by CI as immutable, signable artifacts |
| `HelmRepository` | `https://charts.example.com` or `oci://registry/charts` | An `index.yaml` (classic) or nothing until a chart is requested (OCI) | Third-party and in-house Helm charts |
| `Bucket` | S3-compatible endpoint + `bucketName` | The objects under an optional `prefix` | Manifests generated by a pipeline that writes to object storage |

All four are namespaced, all produce `status.artifact`, and all are
referenced the same way from consumers: `sourceRef: {kind, name, namespace}`.

## Fields that matter

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: demo
  namespace: flux-system
spec:
  interval: 1m                      # how often to check for a new revision (required)
  timeout: 60s                      # per-fetch deadline; default 60s
  url: http://gitea.lab-gitea.svc.cluster.local:3000/lab/demo.git
  ref:
    branch: main                    # or tag: v1.2.0 | semver: ">=1.0.0 <2.0.0" | commit: <sha> | name: refs/heads/main
  secretRef:
    name: demo-git-auth             # username/password, or identity + known_hosts for SSH
  ignore: |                         # .gitignore syntax; default excludes .git*, CI configs (.github/, .gitlab-ci.yml…), images, archives, .sops.yaml
    /*
    !/apps/
  verify:
    mode: HEAD                      # verify the GPG signature of the commit
    secretRef:
      name: gpg-public-keys
```

- **`interval`** is the polling period. It bounds the delay between a push
  and the cluster. It is required on `GitRepository`, `OCIRepository`,
  `Bucket` and `HelmChart`; `HelmRepository` defaults it to `1m` (and ignores
  it for `type: oci`). `url` is the other field you always write.
  Short intervals on hundreds of sources turn into rate limits at your Git
  provider; 1m is fine in the lab, 5-10m is common in production with a
  webhook Receiver for immediacy.
- **`ref`** chooses what to follow. `branch` tracks a moving head; `tag` and
  `commit` are pinned; `semver` follows the highest tag matching a range,
  which is how you promote by tagging. Exactly one of them should be set.
- **`ignore`** removes files *before* the tarball is built: keep secrets,
  docs and large binaries out of the artifact. It does not change the
  revision, which is the resolved commit, so a commit that only touches
  `README.md` still produces a new revision and a reconcile of every
  consumer (which then finds nothing to change), as lesson 2 says.
- **`secretRef`** is the credential. Public HTTP(S) repos, like the lab's
  Gitea, need none. For private repos the Secret holds `username` and
  `password` (a token), or `identity`, `identity.pub` and `known_hosts` for
  SSH.
- **`verify`** turns on signature checks: GPG commit signatures for Git,
  cosign or notation for `OCIRepository` (`verify.provider: cosign`). A
  failed verification is a failed reconcile, so the unsigned content never
  becomes an artifact.

`OCIRepository` adds `ref.tag` / `ref.semver` / `ref.digest` and
`layerSelector`; `HelmRepository` adds `type: oci` for registries;
`Bucket` adds `provider` (`generic`, `aws`, `gcp`, `azure`), `endpoint`,
`region` and `prefix`.

**Why it matters:** the *source* is the trust boundary. Everything a
consumer applies came through a source, so credentials, verification and
`ignore` rules belong here, declared once, rather than on each consumer.

## Revision formats

The `REVISION` column and `status.artifact.revision` follow a fixed shape:
`<ref>@<algorithm>:<hash>`. Learn to parse it and you can tell at a glance
what was fetched.

| Kind | Example revision | Meaning |
|---|---|---|
| `GitRepository` | `main@sha1:5f3c1c8e2d0a…` | branch `main` at that commit |
| `GitRepository` (tag) | `v1.4.0@sha1:0c9d…` | tag and the commit it points to |
| `OCIRepository` | `6.7.1@sha256:9b1e…` | image tag and manifest digest |
| `HelmRepository` | `sha256:2a7f…` | checksum of the downloaded `index.yaml` |
| `HelmChart` | `6.7.1` | the chart version that was packaged |
| `Bucket` | `sha256:c41d…` | checksum over the listed objects |

The separate `status.artifact.digest` is always the checksum of the tarball
itself; consumers use it to verify the tarball they download. They are
*triggered* by a revision change only: an artifact rebuilt at the same
revision (for example after an `ignore` edit) is picked up at the
consumer's next `interval`, because every run re-fetches and re-applies.

## Debugging a source that is not Ready

Work down this list; each step is a read-only command.

1. **Status line.** `flux get sources all -A` shows the one-line message.
   `flux get sources git --status-selector ready=false` narrows it.
2. **Conditions.** `kubectl -n flux-system describe gitrepository <name>`
   and read `Status.Conditions`. The `Ready` condition's **reason** is the
   classifier:

| Reason | Usual cause |
|---|---|
| `GitOperationFailed` | wrong URL, unknown branch/tag, auth failure, TLS error, host unreachable |
| `AuthenticationFailed` | bad or missing `secretRef`, expired token, wrong key format |
| `DirectoryCreationFailed`, `ArchiveOperationFailed` (on the `StorageOperationFailed` condition) | source-controller cannot write its `/data` volume (full, permissions) |
| `VerificationError` | commit or artifact signature does not match the keys in the verify Secret |
| `IndexationFailed` (HelmRepository) | `index.yaml` missing or malformed at that URL |
| `ChartPullError` (HelmChart) | chart name/version not in the index, or registry auth |

3. **Events.** The bottom of `describe` lists the last attempts with
   timestamps; a source that alternates between Ready and failing is a flaky
   network or rate limit, not a config error.
4. **Logs.** `flux logs --kind=GitRepository --name=<name>` has the full
   Git client error when the condition message is truncated.
5. **Reproduce from where the controller runs.** The URL that works on your
   laptop may not resolve from inside the cluster. For the lab Gitea that is
   the difference between `localhost:30080` (terminal) and
   `gitea.lab-gitea.svc.cluster.local:3000` (controllers).

**Gotcha:** a `Ready=True` source with a stale `REVISION` is not broken; it
means the ref has not moved. Check `git log` on the branch you *think* you
pushed to before suspecting Flux. Pushing to `master` while `ref.branch` is
`main` is the classic.

**Try it:** create a repo in the lab Gitea, point a GitRepository at it,
then break one on purpose and read the conditions.

```bash
# 1. an empty repo with a README on branch main (Gitea API, user lab)
curl -s -u lab:labpass123 -H 'Content-Type: application/json' \
  -X POST http://localhost:30080/api/v1/user/repos \
  -d '{"name":"demo","auto_init":true,"default_branch":"main"}' >/dev/null

# 2. a working source (note the in-cluster URL)
flux create source git demo \
  --url=http://gitea.lab-gitea.svc.cluster.local:3000/lab/demo.git \
  --branch=main --interval=1m
flux get sources git
kubectl -n flux-system get gitrepository demo -o jsonpath='{.status.artifact.revision}{"\n"}'

# 3. a broken one: wrong repo name
flux create source git broken \
  --url=http://gitea.lab-gitea.svc.cluster.local:3000/lab/nope.git \
  --branch=main --interval=1m --export | kubectl apply -f -
sleep 15; flux get sources git broken
kubectl -n flux-system describe gitrepository broken | sed -n '/^Status:/,/^Events:/p' | head -30
flux delete source git broken --silent
```

Keep `demo`: the next lesson builds on it. The *flux-first-kustomization*
scenario is self-contained (its own repo and namespace), so you can run it
at any point.
